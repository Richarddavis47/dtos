# Season-performance evidence method

The new adapter reads the existing admitted `season_matchups` publication. It verifies exact league, season, methodology, scoring fingerprint and calendar reference. It uses the existing league completion boundary, not the current roster's player history or current projections. Regular-season averages use supported native team totals only. An explicit non-null custom_points value is the score override; invalid overrides are missing, not a fallback to base points. Zero and negatives remain valid. Repeated equal franchise-week scores count once; conflicting scores withhold that week.

The league comparison requires a unique full configured franchise cohort and every cohort member's score over the same owner-observed weeks. No scoring rank or franchise grade is introduced. Partial observed-week averages disclose their sample. Official record/standing/cumulative figures remain the existing authoritative separate evidence; they are never forced to reconcile to this observed sample.

Recent means up to the latest three completed expected team weeks. Missing weeks remain visible rather than being skipped for positive games. Supported fantasy playoff weeks reuse the existing prepared bracket resolver; bye placeholders are excluded. Ambiguous/missing postseason participation withholds recent scoring. The average remains explicitly regular-season so eliminated and advancing teams are not compared over unequal playoff opportunities.

Fresh publication and stat corrections reach the stateless adapter directly. Production Home's existing generation provider already includes the native season publication generation. The refresh browser fixture publishes a new data object and source generation; it does not mutate a constant-generation fake snapshot. Last-valid score rows retain their original observation clocks and failed-refresh qualification. No source calls, synchronization, solver, heavy lease or permanent store is added to rendering.

Validation uses the pinned Python3.14.3 image and enforced2147483648-byte containers, with2CPUs and network disabled. The official canonical runner and observer are extracted unchanged. Existing8GiB-after-create scratch and stronger pre-create allowance remain intact. Exact commands/limits/identities appear in original invocation records. Event-stream counts alone are not verdicts: complete unittest consoles, actual exits, all ten gates, checksums and cleanup establish completion.

Responsive acceptance is Chromium keyboard/touch emulation at320/375/390/1280, not physicaliPhone/Safari or a user study. Original600px first-player and full-player viewport assertions remain unchanged. A four-column prototype was rejected on actual screenshot inspection; production's original three shortcuts remain. The existing record line is now a44px target linking to the expandable season section. Earlier failures and superseded runs remain distinct from final-source results.
