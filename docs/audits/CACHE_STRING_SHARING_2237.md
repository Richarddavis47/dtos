## Narrow shared boundary and accounting

src/platform/cache_json.py uses the standard JSON decoder with a per-read object hook. Equal string values of2–128characters share references while the pool holds at most65,536entries and16MiB of conservative character accounting. Those are pool bounds, not a claim about complete Python object overhead. The temporary dictionary references already decoded strings; it is released on success/error. There is no sys.intern, permanent source warehouse or cross-account pool. Dicts/lists remain independent, numbers and Unicode retain standard parser semantics, and later source/disclosure mutation cannot alias through shared mutable containers.

Both default services.sleeper.load_cache and connected services.league_preparation.restore_cached_runtime use this helper. Existing retention checks, pinned-file size/generation admission, owned-reader cancellation, exact scope checks, actual-results rebinding and canonical publication remain with their original owners. The writer and persisted JSON are unchanged. Legacy files need no migration. No evidence is omitted and regenerated after a discounted admission: the same full file size still enters the unchanged16× guard. No reserve, telemetry deduction, file-cache credit, heavyweight lease or cleanup policy changes.

The improvement can leave more real headroom when a compatible runtime is resident, but does not reduce the required reservation for a given cache. A cold cache with insufficient capacity still defers, including with unknown telemetry or protected FOIS/Trade/sync work. This does not guarantee Granite admission or establish the cause of the earlier503.
