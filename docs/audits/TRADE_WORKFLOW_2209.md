# Build 2209: Trade workflow and discoverability

## Existing contract and bounded live observation

Build 2208 has separate create/calculator, trade-for, shop and recommended
routes sharing one account/session/league-bound workspace. Generated offers
remain hypothetical. Evaluation, discovery, balancing and adjustment are
explicit operations; targeted Shop/Trade For entries retain their existing
automatic search after a deliberate asset selection. Ordinary Recommended
navigation never starts discovery.

The owner's newly authorized normal HTTPS sign-in succeeded against build
2208. Bounded GETs confirmed private/no-store authenticated pages, a ten-team
workspace and the reported source ordering: strategy and results followed
the asset board. No production package, ranking, preference, league selection,
trade or lineup was changed. Credentials and cookies stayed in memory and are
not evidence files. The connected Browser Work control is unavailable; this
is authenticated HTTP evidence, not a live owner-browser walkthrough.

## Presentation changes

Trade Center identifies Generate Trades (DTOS discovers offers) separately
from Evaluate Trade (the manager supplies an offer). Existing Build, Shop,
Trade For, Recommended and Calculator destinations remain accessible. The
workspace puts purpose, actual context, a visible goal and Neutral/Custom mode
before optional controls and the primary action. Phone pages keep the shared
Trade Center heading and active purpose tab; the duplicate workspace heading
is visually hidden while remaining available to assistive technology.

The goal is no longer behind a disclosure or after the roster. Recommended
owned-asset boards are optional, with all original exact IDs, filters and
selection behavior intact. Shop and Trade For still expose their necessary
target selection. Generated output is directly beneath the primary controls;
explicit search completion focuses the result and reveals its beginning, with fixed
navigation clearance. Initial automatic targeted Shop entry preserves its top
context; a subsequent explicit search focuses results. Calculator/Balance retain their established placements
and price-only versus full-analysis distinction.

## Supported preferences, not a new policy

Win Now, Retool and Rebuild send the unchanged explicit strategy values. No
selected goal sends null and retains existing supported-evidence resolution.
Neutral/Custom mode remains a separate valuation dimension.

Recommended keeps its existing All, Win Now, Value, Roster Fit and Draft
Capital opportunity filters. These select already-supported types; they do
not invent player-versus-pick valuation weights. Sell High stays disabled
without supported movement evidence. Shop retains Best Overall, Win-Now,
Youth/Rebuild, Draft Capital, Position Need and exact-protection preferences
with their existing request semantics. There is no new general "lean toward
players" ranking rule; that remains an unsupported product choice.

Include draft picks defaults on. Turning it off maps only the explicit
generation request to the existing exclusion contract using exact current
pick asset IDs from the authorized workspace. It excludes both outgoing and
incoming picks. No prices, pick aliases or new provider reads are created.
A required Shop/Trade For pick cannot be silently replaced: the UI asks the
manager to enable picks or choose another target. Unseeded Recommended
continues to send null target and zero counterparty even with a retained
draft objective. Echoed temporary pick exclusions never become saved locks.
Manual evaluation and selected packages remain independent of this search
choice. No new persistent preference memory is implemented; new controls
are local to the current page/search. Existing draft and strategy session
retention is preserved, rather than becoming durable account intent.

## Progress, cancellation and recovery

Preparing means the existing authorized workspace GET is pending. Inputs
requiring it remain disabled until ready. Searching/evaluating starts when
the corresponding explicit request is sent. There are no invented percentage
or server substage claims. Complete requires a successful, structurally valid
response for the requested workflow; an incomplete HTTP-200 search is an
error, not an empty successful search. Errors preserve the original package
and expose retry through the existing action. Workspace failure has an
explicit reload/recovery control.

The live announcement mirrors visible progress outside the busy workspace.
The existing workspace busy contract and disabled duplicate actions remain intact.
Cancellation uses the established AbortController and revision/run-sequence
guards; it stops the client from accepting the result, not a promise that
all server cleanup has already finished. A delayed response cannot revive an
old strategy, mode or cancelled search. Focus returns to an enabled primary
action when the cancellation button disappears. No new polling or job is added.

## Final bilateral qualification

The existing final verdict remains authoritative in cards, previews and
evaluation. The presentation groups as qualified recommendations only rows
with generated eligibility and a final SMASH ACCEPT/WORTH PURSUING verdict,
never exploratory rows. FAIR/OPTIONAL, counterparty-limited and other
nonqualified rows remain available separately, without changing their
eligibility, prices or original labels. Zero qualified results is explicit;
optional offers do not imply failed pricing or a rejected legal package.
Rejected/unsupported near misses retain their evidence disclosure.

Preview, Keep, Adopt, Adjust and Balance retain exact package identity, selected
mode, targets and protections. The established primary-navigation fresh-entry
policy is unchanged. No site-wide Back feature is introduced.

## Validation and preservation

Disposable source -> store -> HTTP -> Chromium checks exercise the distinct
purpose routes, unseeded strategies, modes, exact pick exclusions, optional
filters, failure/retry, incomplete responses, delayed preparation, duplicate
submission, cancellation despite ineffective abort delivery, late responses,
keyboard focus, pointer/emulated touch and four viewport sizes. Existing
business, identity, account/league, historical and Trade safeguards remain
mandatory. Updated legacy helpers merely open the newly optional inventory
or use the now-visible strategy; their outcome assertions remain intact.

No provider adapter, Trade engine, ranking mathematics, projection, optimizer,
historical grade, account boundary or public Welcome implementation changes.
All roster rows are still prepared/rendered: a collapsed disclosure is not
claimed to make computation lazy. The UI reuses existing prepared assets and
requests; no anonymous calculation, persistent analytical storage, additional
polling or infrastructure is added. Two-GiB and independent liveness controls
remain mandatory. Controlled Chromium is not physical iPhone/Safari, an
unfamiliar-human study or sustained production-capacity acceptance.

Failed, timed-out, cleanup/fixture and incomplete attempts remain separate
from exact-final-source release admission. Release requires all ten canonical
gates, complete Product/security/navigation, focused and lifecycle checks,
followed by source-tree, immutable release and production identity verification.
