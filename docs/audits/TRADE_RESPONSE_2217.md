## Narrow correction

Package evaluation prepares canonical pre-trade diagnostic inputs once and independently constructs post-trade inputs once. It decodes the admitted league baseline once and copies the selected teams' strategy views from that same result. Public league/team consumers retain their existing read-time admission and cache contracts.

A refresh failure can qualify an unchanged publication while package assembly is running. Both selected pre-views are requalified at the latest shared boundary before comparison; an earlier current label must not survive a new retained-publication qualification. Post-trade eligibility and evidence are always prepared independently, including incoming Out/inactive, reserve and unknown players. No inputs, solver calls, candidate evaluations, ownership checks or final thresholds are skipped.

The change adds no cache or persistent state. Existing bounded diagnostic and lineup stores, TTLs, byte/entry caps and request isolation are unchanged. Returned team views remain copies. Neutral/Custom mathematics, exact picks, strategy isolation, historical grades, source-generation fences and account/league authorization are unchanged.

Twelve serial alternating-order source-compatible comparison pairs cover 2,160 complete evaluated package results. Frozen build 2216 and the final package implementation produce identical packages and result digests. The ten-franchise full-roster Rebuild control takes 12.34/13.02 seconds before and 10.43/10.10 afterward; the partly occupied control takes 12.59/12.88 before and 10.63/10.42 afterward. All 180 evaluations still run. All strategies are included. These synthetic large-league cases correctly return zero qualified offers; separate qualified package and browser controls remain mandatory. These shared-executor measurements do not predict a fixed production duration or broad capacity.

## Cold preparation qualification

The recorded post-deployment Market and My DTOS 503 responses have no retained body or preparation headers. The recorder found no structured runtime-acquisition code, while the accepted runtime-error middleware always emits one. Market warming can produce this pattern and later normal browser access recovered, but the exact historical source/preparation phase cannot be proven retroactively. Global readiness does not establish a prepared private-league Market publication. No speculative health/readiness or admission-policy change is made.

Controlled coverage must distinguish runtime hydration, delayed/failed/incompatible Market preparation, preserved last-valid values, bounded status checks and successful recovery. Never reclassify absent prices as zero or launch production stress to recreate a cold failure.

## Cancellation and performance limits

The existing manager-read executor uses asyncio.to_thread. Cancelling its await does not preempt synchronous work already running; that existing bounded search completes. Browser Cancel suppresses late results and does not automatically submit another search. This release does not claim instant CPU cancellation or add a cancellation protocol, queue, worker service, polling or concurrency increase. Observe completion/timeout cleanup and disclose remaining in-flight work accurately.

Before release, compare frozen build 2216 and candidate package code on identical publications with cold and warm stores, all strategies, full/partly occupied rosters, complete evaluated-package/result equality and guarded source-call counters. Preserve source-refresh and missing/zero controls, responsive browser interactions and original failed/incomplete attempts. Timing runs must be serial and unprofiled; retain contended attempts separately. Full canonical validation, hosted Product/security/navigation and actual 2 GiB lifecycle checks remain mandatory. Controlled Chromium is not physical Safari, and raw lifecycle peaks do not establish production headroom.
