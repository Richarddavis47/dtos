# Shop search policy

Shop is a search adapter over the accepted bilateral evaluator, not a valuation or grading engine.

## Discovery and construction

The shopped asset must belong to the active franchise. All other canonical league rosters are potential counterparties, not assumed buyers. Discovery admits priced return pools and respects requested position/capital availability. Unknown team strategy does not become a negative assumption. Final buyer rationale comes from the shared proposal assessment.

The constructor retains the shopped asset, uses bounded position/type-diverse shortlists and at most six package shapes per counterparty, then restores the user-sends perspective. Preferences requesting a position or pick return constrain construction before evaluation. Protected/excluded assets never enter forbidden packages. Protecting the shopped asset returns an explicit constraint no-result.

## Preference ordering

Preferences are single-choice request/session controls, never permanent manager strategy. There is no opaque Shop score. All options first require the unchanged generated-workflow legality, rational-user-return and bilateral-plausibility safeguards. Unsupported dimensions remain unavailable.

| Preference | Search/ordering contract |
|---|---|
| Best Overall | Shared user recommendation, counterparty plausibility, confidence, observed loss weeks, then supported horizon/depth differences. Not raw Market total. |
| Win-Now | Supported current-week, next-N, regular-season and playoff-window deltas in that order, then reserve slot-week change and shared quality. No age shortcut. |
| Youth / Rebuild | Shared quality safeguards first; among comparable returns, observed age of actual incoming lineup contributors, then explicit future-capital count. Age is descriptive, not projected career length, durability, liquidity or intrinsic dynasty value. Missing longevity/liquidity is disclosed. |
| Draft Capital | Requires owned priced picks during construction; shared quality first, then pick-bearing portfolio count and supported lineup effects. Pick identity, original franchise, range, confidence and Market quote remain separate in canonical future-capital evidence. |
| Position Need | Requires the position during construction and actual incoming optimal-lineup contribution before surfacing a result. A position label alone is insufficient. Then uses supported horizon/depth ordering. |
| Custom | Uses the visible protected-assets control (and supported API excluded-assets constraint); otherwise default supported ordering. No free-text personalization or Adjust intelligence is inferred. |

Numerical deltas are never filled from missing evidence. Preference ordering does not alter any canonical evaluation field. Unsupported or conflicting preference parameters reject explicitly.

## Markets, returns and interaction

A market contains a counterparty, its shared buyer rationale and up to three materially distinct qualified constructions. Nominal interchangeable pick swaps do not fill extra slots. At most five markets surface; fewer or none is valid. The best supported construction orders each market rather than assets the user merely wishes to acquire.

Every return opens the common editable proposal. The shopped asset remains fixed until Build My Own leaves the workflow. Adjust receives exact assets/counterparty without Shop preferences. Fresh navigation/asset selection resets preference controls. Account/session/league ownership guards and generation-bound search reads remain in effect.

## Evidence and performance

Prepared pre-trade evidence and pinned projection-week reads are reused within a search. Package-specific hypothetical lineups remain independent. Search performs no durable writes or source refresh. Real diagnostic reports stay private; fixture positive results are never represented as real current-league offers. No result count or latency threshold is fabricated.
